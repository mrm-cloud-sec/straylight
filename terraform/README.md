# Terraform Infrastructure

## Overview
Modular Terraform configuration for red team infrastructure deployment. Deploys a secure VPC with attack servers, C2 servers, redirectors, and VPN infrastructure.

## Quick Start
```bash
cd terraform/
terraform init
terraform plan
terraform apply
```

## Module Structure
```
modules/
├── cdn/           # CloudFront distributions, Route53 records, ACM certificates
├── compute/       # EC2 instances (VPN, Redirector, C2, Attack)
├── networking/    # VPC, subnets, routing, NAT gateways, VPC endpoints
├── security/      # Security groups, IAM roles/policies
└── storage/       # EFS, S3 buckets, CloudWatch log groups
```

## Security Model

### Network Access
- **Internet → VPN**: Port 51820 (WireGuard UDP)
- **CloudFront → Redirector**: Port 443 from the AWS-managed origin network
- **Internet → Redirector**: Ports 80/443 only when CloudFront is disabled
- **VPN Users → All Servers**: SSH (port 22) + service ports

### Security Groups (Sliver)
- **C2 (from Redirector subnet)**: HTTP C2 (8888)
- **C2 (from VPN subnet)**: mTLS (4444), operator gRPC (31337), SSH (22)
- **Redirector**: HTTPS (443) from CloudFront origins, SSH from VPN subnet; direct HTTP/HTTPS is a non-CloudFront fallback
- **VPN**: WireGuard (51820/UDP) from internet
- **Attack**: SSH from VPN subnet only

### IAM & Instance Profiles
- Shared IAM instance profile with SSM permissions
- S3 access scoped to operation-specific bucket

## Configuration
Primary configuration via `terraform.tfvars` (generated by `deployer.py`):
```hcl
aws_region                    = "eu-west-1"
vpc_cidr                      = "10.0.0.0/16"
operation_name                = "your_operation"
enable_cloudfront             = true
cloudfront_distribution_count = 10
domain_name                   = "example.com"   # your Route53 hosted zone
```

### Key Variables
| Variable | Default | Description |
|----------|---------|-------------|
| `aws_region` | eu-west-1 | AWS deployment region |
| `operation_name` | — | Unique identifier (lowercase, underscores) |
| `vpc_cidr` | 10.0.0.0/16 | VPC CIDR block |
| `enable_cloudfront` | true | Enable CloudFront domain fronting |
| `cloudfront_distribution_count` | 10 | CloudFront distributions (1-25) |
| `domain_name` | — | Route53 hosted zone you control |
| `log_retention_days` | 90 | CloudWatch log retention |

## CloudFront / CDN (Optional)

When `enable_cloudfront = true`, the CDN module creates:
- **Route53 subdomain**: random hex string (e.g. `a3f8c1d2e4b5.example.com`) — avoids leaking operation name in public DNS
- **ACM certificate**: DNS-validated via Route53
- **CloudFront distributions**: Multiple `*.cloudfront.net` domains pointing to the subdomain

## Cost Optimization
- **Root volumes**: 20GB (VPN/redirector), 200GB (C2), 50GB (attack)
- **EFS**: Bursting throughput mode
- **Instance types**: t3.medium for C2, t3.micro for others

## State Management
Never commit `terraform.tfstate*`. After deployment, `deployer.py` uploads state to S3:
`s3://{operation-bucket}/terraform/terraform.tfstate`

## Implementation Details

### Bootstrap Process
`ssm-bootstrap.sh` only installs SSM agent. All other configuration is Ansible's job.

### NAT Gateway Timing
Private subnet instances (C2/Attack) require NAT Gateway for internet access. `base-hardening.yml` handles apt updates with retries to account for NAT readiness delay.

### Security Features
- **IMDSv2**: Enforced on all instances, IMDSv1 disabled
- **VPC Endpoints**: SSM, SSM Messages, EC2 Messages — private subnet connectivity without NAT
- **Encrypted Storage**: All EBS volumes encrypted at rest
